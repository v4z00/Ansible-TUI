Ansible TUI local API

The service accepts one JSON request per line over its Unix socket. Run queries as
the account that owns the service. Replies have the form {"ok":true,"data":...}
or {"ok":false,"error":"..."}. Example:

ansible-tui api '{"method":"catalog.list","lang":"en"}'

Catalog and inventory
  status, catalog.list, catalog.refresh, jobs.list, events.list
  completion.query {source:"inventory.targets",prefix:"demo"}
  inventory.refresh executes the configured inventory, including any API plugins.
  hosts.list returns resolved connection data held in memory.
  catalog.list accepts lang:"de" or "en" per request. The cache holds both languages.
  Target suggestions come from an unambiguous, existing group named in the
  command's playbooks. control.defaults {command} returns values and hint.
  It can load inventory when an operator asks for defaults.

Start a job (explicit operator action)
  {"method":"control.start","command":"base","values":{"targets":["demo"]}}
  {"method":"control.start","command":"bootstrap","args":["--target","demo"]}
  {"method":"playbook.start","playbook":"playbooks/site.yml","limit":"demo","check":true}
  {"method":"ssh.start","host":"demo"}
  {"method":"tunnel.start","host":"demo","local_port":15432,"target":"db.example.invalid","target_port":5432}
  {"method":"docker.start","host":"demo","container":"abc123","action":"logs"}
  {"method":"docker.start","host":"demo","container":"abc123","action":"restart","confirm":"demo:abc123:restart"}
  {"method":"compose.edit","file":"demo/stack/compose.yml"}
  {"method":"job.stop","id":"JOB-ID","confirm":"JOB-ID"}

  Standalone playbooks must exist in the catalog. check enables --check, limit
  sets --limit and inventory comes from project configuration. With tmux off,
  send terminal:true. The reply supplies id and direct_path for a one-time
  local run-job invocation. An unclaimed start expires. With tmux on,
  opening a foreground job selects its returned pane after starting the job.
  Avoid credentials in args; private job files retain the arguments.
  The service does not automatically retry jobs.

Docker and Compose
  docker.list {host}, docker.stats {host}, docker.inspect {host,container},
  compose.list {host}. These are explicit queries. Container actions are logs,
  shell, start, stop and restart. Compose uses nano and keeps a private before-image.
  Run the relevant deployment command separately after editing.
  docker.discover {force?:bool} starts asynchronous discovery when needed.
  docker.hosts returns hosts[{host,state,loading,containers,at,error}] plus
  discovering, inventory_loaded, error, group and group_present.
  docker.snapshot {host} returns host,rows,at,state,error for a deployment host.
  The snapshot is pending before the first result. Failed polls retain the last
  successful rows and time; an empty successful result is ready.
  hosts.list includes the docker_deployment boolean. The service keeps the cache
  in memory and does not periodically rerun inventory. A service restart clears
  it. Background polling starts after an explicit inventory load or Docker visit.

Preferences
  settings.get returns values,preferences_file,project,inventory_loaded,host_count
  and related state. settings.update {values} validates and atomically saves a
  complete typed preference set (0600). It takes effect without target actions.
  docker_enabled, tmux_enabled and ssh_enabled control integrations. docker_auto_ack
  applies to new jobs, docker_auto_focus takes effect immediately. jobs.list can
  supply auto_focus, needs_input and an interaction_token for pending input.
  No prompt or answer is recorded in the marker.
  inventory.clear {confirm:"clear-cache"} clears in-memory mappings and discards
  old in-flight responses. Running jobs and files are retained.

Logs and maintenance
  job.capture {id,confirm:id} enables output recording (five files of 10 MiB).
  job.log.read {id} returns the latest 256 KiB or {output:""} for an empty log.
  job.ack {id,confirm:id} acknowledges a finished failure or cancellation.
  jobs.list then includes acknowledged_at in RFC 3339. The exit code and state
  are retained. Acknowledgements survive service restarts.
  job.log.clear {id,confirm:id} removes a finished job's log and rotations.
  job.close {id,confirm:id} closes that finished job's identified pane.
  events.clear {confirm:"clear-events"} clears events and records the clear.
  These four operations return {maintenance:true,message:...}. SQLite schema 2
  stores acknowledgements in job_acknowledgements. Job results are retained.

tmux
  tmux.list returns {servers:[{label,available,sessions:[{id,name,windows,
  clients,socket}]}],output} for the configured and default sockets. Missing
  servers return available:false. The CLI command ansible-tui tmux works
  without the service. Idle private sessions are closed only when they contain
  no clients, UI, active or uncertain jobs, or unidentified windows.
