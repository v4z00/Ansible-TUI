ERWEITERUNG 0.1.3 - DOCKER-DEPLOYMENTCACHE
hosts.list: zusaetzliches Boolean docker_deployment, keine rohen Hostvars/Tags.
docker.discover {force?: bool}: sofortige Antwort; Inventory im Hintergrund,
  falls noch nicht geladen oder force=true. Kein periodischer Inventorylauf.
docker.hosts: {hosts:[{host,state,loading,containers,at,error}],
  discovering,inventory_loaded,error,group,group_present}. state pending/ready/error.
  Kompakte Zusammenfassungen ohne Containerzeilen. Rein lesend, keine SSH-Abfrage.
docker.snapshot {host}: letztes {host,rows,at,state,error}; nur Deploymenthosts.
  Rein lesender RAM-Cache, pending vor erstem Ergebnis, error bewahrt letzte rows/at.
  Erfolgreiche leere rows sind bereit, fehlende Ergebnisse dagegen pending/error.
Bestehende docker.list/stats/inspect-Aktionen bleiben explizite direkte Abfragen.
Cachepoller startet nach bewusstem Inventoryladen oder Dockerbereichsaufruf.
Koordinator-Neustart leert Cache, tmux-Jobs bleiben davon unabhaengig.

Katalogsprache / Catalog language

The catalog accepts de or en. For example: ansible-tui --lang en ui.
Command help, description text and field labels follow --lang, CONTROLLER_LANG,
then the configured controller language. Legacy projects default to German.
catalog.list accepts a per-request lang. Concurrent clients can select
different languages. SQLite caches one canonical record with both translations.
A language change requires no catalog refresh. A missing translation uses the
existing schema_version 1 title, field help or Markdown body. Source hashes,
bindings, command names, constraints and submitted values do not change.
